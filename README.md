# Multi Server — Backend-connected starter

This package connects the previously built storefront to a Node/Express backend. It is intentionally **demo payment / demo license** until the real payment provider and your legitimate license-generation API are integrated.

## Requirements
- Node.js 20+
- For persistent production data: PostgreSQL and `DATABASE_URL`

## Run locally (fast demo)
1. Copy `.env.example` to `.env`.
2. Keep `DEMO_MODE=true` and set your own `JWT_SECRET`, `ADMIN_PASSWORD`, and `ADMIN_SECRET`.
3. Run `npm install`.
4. Run `npm start`.
5. Open `http://localhost:3000`.

Without `DATABASE_URL`, the app uses in-memory demo data. Restarting the server resets orders. Do not use that mode for a real store.

## Production
Use PostgreSQL by setting `DATABASE_URL`. Put the app behind HTTPS and set `NODE_ENV=production`. Use a strong random `JWT_SECRET`. Change all admin credentials. Disable `DEMO_MODE` before real payment integration.

## API outline
- `GET /api/health`
- `GET /api/products`
- `POST /api/orders` — creates a pending order
- `POST /api/orders/:id/demo-pay` — demo-only payment completion
- `POST /api/auth/login` — admin login
- `GET /api/admin/stats` — protected
- `GET /api/admin/products` — protected
- `GET /api/admin/orders` — protected

## Next integration
The `issueLicense()` function in `server.js` is the integration point for the license-generation service. When you provide the API documentation, wire its authenticated request there. For a real payment provider, add a provider-specific webhook endpoint that verifies the provider signature and only then changes an order to PAID and issues a license.


### Admin dashboard
The dashboard now loads Recent Orders from `/api/admin/orders` and resolves product names from the live product API instead of using placeholder order rows.


## Temporary UPIQRPay integration
This version integrates UPIQRPay's documented create-order endpoint, HMAC-SHA256 webhook verification, and status endpoint as a fallback. It does not include the real license-provider integration yet.

Set these in `.env`:
- `DEMO_MODE=false`
- `UPIQRPAY_BASE_URL=https://upiqrpay.in/api/v1`
- `UPIQRPAY_API_KEY=<your secret API key>`
- `UPIQRPAY_WEBHOOK_SECRET=<your webhook secret>`
- `PUBLIC_BASE_URL=https://<your temporary HTTPS tunnel URL>`

The browser never receives the UPIQRPay API key or webhook secret. The backend creates the provider order and returns the provider's QR/payment URL to the browser.

For a temporary local test, your HTTPS tunnel should forward `PUBLIC_BASE_URL` to `http://localhost:3000`. Configure UPIQRPay's webhook URL as `${PUBLIC_BASE_URL}/api/webhooks/upiqrpay`.

The payment webhook is primary. The backend verifies `x-UPIQRPay-Signature` using HMAC-SHA256, checks the internal order ID and amount, and processes a successful payment only once. The status API is used only as a controlled fallback while an order is pending.

After payment succeeds, `licence_status` is left as `PENDING` until the separate legitimate licence API is integrated. No fake licence is generated by the real payment flow.
